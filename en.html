01 · Background

Where I come from

I grew up in Senegal, in a farming family. As a child, I spent a lot of my time in the fields with my father, growing peanuts, rice and maize.

That is where I learned to work on something for a long time before seeing the result. After my science baccalaureate, I came to France in 2024 to study Networks and Telecoms at IUT de Roanne, then I moved on to Colmar for the DevCloud track.

What interests me is understanding what really happens when a service goes down. During my internship, that meant finding out why scanned documents no longer arrived by email (a Google security rule was silently blocking them), or why the DECT phones stopped working after a power cut.

Outside of class, I play football and I am involved in the Senegalese association of Roanne and Colmar.

Internship · April → June 2026

Banque Alimentaire du Bas-Rhin

The internship

Banque Alimentaire du Bas-Rhin (a food bank), IT technician intern. From 20 April to 12 June 2026, 8 weeks at 35 hours a week. Supervisor: Alexis Brandt, General Services Coordinator.

Tasks

Automatic printer monitoring. SNMP batch script that runs every night at 2:00 am. Ink levels are updated automatically in GLPI, with automatic email alerts from 15%.

Scan to Email setup. Gmail SMTP configuration on an HP Color LaserJet MFP E57540, with authentication through a Google app password.

Rolling out the GLPI ticketing system. Full setup of GLPI ticketing: user accounts, handling workflow, automatic notifications at every step.

Recovering Microsoft Office licences. Manual recovery with OSPP.VBS and import into GLPI of the Microsoft Office licences on 24 of the 25 computers.

Fixing the DECT phone outage. Diagnosis of a loss of sync on the 3 DECT base stations after a power cut. Resynchronised in 50 minutes by restarting each base in a controlled order.

Active Directory deployment plan. Research on Synology Directory Server and Samba 4. Wrote a complete 24-step plan for the Active Directory integration.

SAE 3.03 · BUT2

Multi-site network, LAN part

Role

In charge of the LAN part · Team of 3 students

Skills used

AdministerConnectDevelop

Context

Design and configuration of the LAN architecture of two fictional companies in GNS3. Three-tier hierarchical architecture, IP addressing plan for 3 sites, VLANs 10/20/30/40, 802.1Q trunks, VTP, MSTP, Router-on-a-Stick inter-VLAN routing, VRRP high availability, and a DHCP service with static addresses for the servers.

Learning outcomes (AC)

  • AC21.01Configure and troubleshoot dynamic routing in a network
  • AC21.02Configure and explain a simple QoS policy and the basic security functions of a network
  • AC21.03Deploy client workstations and virtualised solutions suited to a given situation
  • AC21.04Deploy advanced network services
  • AC21.05Identify operator networks and the architecture of the Internet
  • AC21.06Work in a team to develop professional skills
  • AC22.02Set up secure remote access
  • AC22.03Set up a multi-site connection through an operator network
  • AC24.02DevCloudVirtualise an environment

Reflection

This project was the first time I put a complete network infrastructure into practice in realistic conditions. Designing the IP addressing plan for two companies across three sites took real thinking: every VLAN and every mask had to follow a precise logic.

The main difficulty was coordination within the group. My LAN part had to match the services part and the interconnection part built by my teammates. It taught me to communicate on technical topics and to explain my addressing choices so the others could build on them.

Being in charge of the LAN part also taught me to make important technical decisions on my own: the hierarchical architecture, the choice of MSTP, the VRRP configuration for high availability. Each decision had an impact on the rest of the project.

What I mainly take away from it: a network is not configured in isolated pieces. Everything is connected, and working on this project is what made me really understand the overall logic of a company network.

SAE 3.02 · BUT2

Building communicating applications

Role

Individual project · 2025-2026

Skills used

Program

Context

Design and implementation of an anonymous communication system inspired by the Tor network, using onion routing. The project includes a Master server that keeps track of the routers, several virtual routers doing multi-hop routing, two-way clients with a PyQt graphical interface, layered RSA asymmetric encryption and a MariaDB database. Deployed on 3 virtual machines: 1 Linux VM for the Master, 1 Linux VM for the routers, 1 Windows VM for the clients. Built on my own, from design to deployment.

Learning outcomes (AC)

  • AC23.01Automate system administration with scripts
  • AC23.02Develop an application from given specifications, for the web or mobile devices
  • AC23.03Use a network protocol to program a client/server application
  • AC23.04Install and administer a database management system
  • AC23.05Access a dataset from an application and/or a website

Reflection

I learned a lot from this project. Before starting it, I had only touched on cryptography in first year, never at this depth. Network sockets in Python were also new to me. Understanding how a message can go through several routers without anyone knowing where it came from really fascinated me. Implementing it myself, layer by layer, was a real technical challenge.

The main difficulty I ran into was testing on several virtual machines. My own PC did not have enough resources to run 3 VMs at the same time: it kept crashing and freezing. The project started just before the December holidays, so I could not use the IUT computers. In the end I bought a new PC with 32 GB of RAM and 1 TB of storage so I could test properly.

This project also taught me to work independently. Doing everything alone, from design to development, testing, documentation and deployment, is a complete experience. I had to make every decision and solve every problem myself, and keep moving without being able to rely on anyone else.

Today I know how to deploy an application on several virtual machines that talk to each other over a network. It is a concrete skill I can reuse in any infrastructure project.

SAE 3.01 · BUT2

Wi-Fi smart plug

Role

Web server developer · Team of 4 students

Skills used

DevelopProgram

Context

IoT project in a team of 4: design of a Wi-Fi smart plug that can be controlled remotely. The system includes 2 ESP8266 boards driving LEDs, a DS18B20 temperature sensor, a physical button with debouncing, NTP time sync and real-time MQTT communication through the test.mosquitto.org broker. My part: the Django web server on a Raspberry Pi, with a REST API secured by JWT authentication and a real-time control interface to switch LED1 and LED2 on and off, show the live temperature and manage automatic time slots.

Learning outcomes (AC)

  • AC21.06Work in a team to develop professional skills
  • AC22.05Be able to question a networks and telecoms specification
  • AC23.02Develop an application from given specifications, for the web or mobile devices
  • AC23.03Use a network protocol to program a client/server application
  • AC23.04Install and administer a database management system
  • AC23.05Access a dataset from an application and/or a website

Reflection

It was the first time I built a web application connected to a real embedded system. The main difficulty was getting Django, MQTT and the ESP8266 boards to talk to each other smoothly at the same time. The web interface had to show the real state of the LEDs with no visible delay. This project taught me to work where software meets hardware, two worlds with their own constraints that you have to learn to connect.

This project taught me to move from one environment to another without losing the logic of what I wanted to do. On the creative side, the most interesting part was taking the same pattern-generation algorithm and rewriting it in another language, from Python to JavaScript, while keeping the spirit of the original artwork. I understood that the same problem can be solved in several ways depending on the environment, and that the real skill is understanding the logic behind the code, not just the syntax of one language.
